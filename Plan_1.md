# План разработки Text-to-Text переводчика: Русский ↔ Северокорейский (Munhwao)

## 1. Контекст и Архитектура проекта

**Задача:** Создать систему машинного перевода между русским языком и северокорейским стандартом (Munhwao / 문화어).

**Главная проблема:** В мире не существует качественных открытых датасетов и моделей для прямой пары `Русский ↔ Северокорейский`. Все существующие модели обучены на южнокорейском языке.

**Решение (Архитектура "Корейский Мост"):**
Мы не обучаем модели с нуля и не дообучаем их. Мы используем готовые, предобученные модели и строим цепочку из двух этапов:
1. **RU ↔ SK (Южнокорейский):** Используем мощные существующие open-source модели (MarianMT или NLLB), которые идеально справляются с базовым переводом.
2. **SK ↔ NK (Северокорейский):** Используем готовые специализированные диалектные модели (KoBART), которые конвертируют лексику, орфографию и синтаксис из южнокорейского стандарта в северокорейский (Munhwao) и обратно.

**Итоговый пайплайн:**
*   **RU → NK:** `Русский` → (Модель RU→SK) → `Южнокорейский` → (Модель SK→NK) → `Северокорейский` → (Пост-обработка словарями) → `Финальный Munhwao`.
*   **NK → RU:** `Северокорейский` → (Морф. анализ + Модель NK→SK) → `Южнокорейский` → (Модель SK→RU) → `Русский`.

## 2. Системные требования (Инференс на CPU)

Проект спроектирован так, чтобы работать на обычных пользовательских компьютерах без необходимости использования мощных серверов или облачных кластеров.

*   **RAM (Оперативная память):**
    *   **8 ГБ:** Минимально допустимый объем для запуска связки `MarianMT + KoBART + MeCab`. Система будет работать стабильно.
    *   **16 ГБ:** Рекомендуемый объем для комфортной работы, особенно если используется более тяжелая базовая модель `Facebook NLLB-200-600M`.
*   **Процессор (CPU):**
    *   Для инференса (генерации перевода) **не требуется видеокарта (GPU)**.
    *   Связка `MarianMT + KoBART` переводит предложения практически мгновенно (0.1 - 0.5 сек) на любом современном 4-ядерном процессоре.
    *   Модель `Facebook NLLB-200-600M` переводит предложение за 1-3 секунды на CPU (Intel Core i5/i7 или AMD Ryzen 5/7 последних поколений).
*   **VRAM (Видеопамять):** Не требуется. Проект полностью работоспособен в режиме `device="cpu"`.

## 3. Золотой стек репозиториев (Must-Have)

Эти 6 репозиториев составляют ядро системы.

### 🧠 Ядро (Диалектная конвертация SK ↔ NK)
1. **[nth221/KoreanUnificationParallelCorpus](https://github.com/nth221/KoreanUnificationParallelCorpus)** (Лицензия: GFDL)
   *   **Что это:** 130,738 пар предложений и **готовые бинарные веса** моделей на базе KoBART для перевода `SK → NK` и `NK → SK`.
   *   **Что брать:** Папку `ModelBinary` (готовые `.bin` файлы моделей).
   *   **Роль:** Сердце системы. Превращает южнокорейский текст в северокорейский стандарт. Модель используется "как есть" (без дообучения).

### 📖 Словари и Обогащение лексики
2. **[digitalprk/dump_samhung](https://github.com/digitalprk/dump_samhung)**
   *   **Что это:** Скрипты для извлечения данных из многоязычного словаря Samhung (официальный словарь КНДР).
   *   **Роль:** Дает пары `Русский ↔ Северокорейский` для замены современных терминов, которых нет в корпусе `nth221`.

3. **[digitalprk/dump_biyak](https://github.com/digitalprk/dump_biyak)**
   *   **Что это:** Скрипт для извлечения научно-технического словаря КНДР.
   *   **Роль:** Критически важен для корректного перевода IT, инженерной и научной лексики.

### 🛠️ Инструменты обработки текста
4. **[okikirmui/nkhandic](https://github.com/okikirmui/nkhandic)** (Лицензия: BSD-3-Clause)
   *   **Что это:** Морфологический анализатор (MeCab) и Python-пакет `handic`, перетренированный на 220,000 северокорейских словах.
   *   **Роль:** Правильно разбивает северокорейские агглютинативные слова на корни и суффиксы перед подачей в нейросеть.

5. **[XPDevs/Learn-Munhwao](https://github.com/XPDevs/Learn-Munhwao)** (Лицензия: MIT)
   *   **Что это:** Полноценное PWA-приложение для изучения Munhwao.
   *   **Что брать:** 
       *   Файл `data/dict.js` (готовый словарь сравнения Юг ↔ Север для пост-обработки).
       *   `index.html`, `style.css`, `js/` (готовый UI).
   *   **Роль:** Источник готового интерфейса и правил лексической стилизации.

### 🔧 Утилиты (Сбор данных)
6. **[digitalprk/euc-kp-to-unicode](https://github.com/digitalprk/euc-kp-to-unicode)**
   *   **Что это:** Конвертер из северокорейской кодировки KPS 9566 (EUC-KP) в UTF-8.
   *   **Роль:** Необходим для корректного парсинга оригинальных текстов КНДР при тестировании системы.

## 4. Базовые модели (Hugging Face)

Для связки `Русский ↔ Южнокорейский` используйте готовые модели из Hugging Face Hub.

**Рекомендация для слабых ПК (без GPU):**
*   **Helsinki-NLP/opus-mt-ru-ko** (Легкая, быстрая, идеальна для CPU).
*   **Helsinki-NLP/opus-mt-ko-ru** (Обратное направление).

**Рекомендация для более высокого качества (при наличии 16 ГБ RAM):**
*   **facebook/nllb-200-distilled-600M** (Тяжелее, но лучше понимает контекст). При загрузке используйте квантование до `torch.int8` для экономии памяти и ускорения на CPU.

## 5. Пошаговый план реализации (Roadmap)

### Этап 1: Подготовка окружения и Базового перевода (RU ↔ SK)
1.  Развернуть локальное окружение Python (PyTorch CPU, Transformers, FastAPI).
2.  Реализовать функцию `translate_ru_to_sk(text)`, использующую `Helsinki-NLP/opus-mt-ru-ko`.
3.  Реализовать функцию `translate_sk_to_ru(text)`, использующую `Helsinki-NLP/opus-mt-ko-ru`.
4.  *Результат этапа:* Работающий прототип, переводящий Русский ↔ Южнокорейский на чистом CPU.

### Этап 2: Интеграция "Корейского Моста" (SK ↔ NK)
1.  Склонировать `nth221/KoreanUnificationParallelCorpus`.
2.  Извлечь бинарные модели из папки `ModelBinary` и загрузить их через `transformers` (как KoBART).
3.  Реализовать функции `convert_sk_to_nk(text)` и `convert_nk_to_sk(text)`.
4.  Соединить пайплайны: `RU -> SK -> NK` и `NK -> SK -> RU`.
5.  *Результат этапа:* Переводчик работает, но лексика может быть устаревшей (уровня классических романов).

### Этап 3: Пост-обработка и Обогащение (Самый важный этап для качества)
1.  Склонировать `digitalprk/dump_samhung` и `digitalprk/dump_biyak`.
2.  Запустить скрипты парсинга, выгрузить данные в формат JSON/CSV.
3.  Склонировать `XPDevs/Learn-Munhwao`, извлечь `data/dict.js` в Python-словарь.
4.  Написать скрипт **Post-Processing**:
    *   Принимает текст от модели KoBART.
    *   Ищет южнокорейские слова и заменяет их на современные северокорейские аналоги из Samhung/Biyak.
    *   Применяет Regex-правила для замены грамматических окончаний: `-습니다` → `-습네다`, `-입니다` → `-입네다`.
5.  *Результат этапа:* Переводчик выдает аутентичный современный Munhwao.

### Этап 4: Морфология (Для направления NK → RU)
1.  Установить `pip install handic mecab-python3 jamotools`.
2.  Скачать бинарный словарь из Releases репозитория `okikirmui/nkhandic`.
3.  Добавить шаг морфологического разбора перед подачей северокорейского текста в модель `convert_nk_to_sk`.

### Этап 5: Интерфейс (UI)
1.  Взять фронтенд из `XPDevs/Learn-Munhwao`.
2.  Настроить локальный сервер (например, `python -m http.server 8000`).
3.  В JS-коде приложения заменить локальную логику на API-запросы к вашему Python-бэкенду (FastAPI), который выполняет полный пайплайн.

## 6. Стек технологий и оптимизация

*   **Язык:** Python 3.10+
*   **ML Фреймворки:** PyTorch (CPU версия), Hugging Face `transformers`, `optimum` (для оптимизации на CPU).
*   **NLP Инструменты:** MeCab (через `handic`), `jamotools` (для конвертации в Jamo).
*   **Backend:** FastAPI (для создания REST API из Python-пайплайна).
*   **Frontend:** HTML/CSS/JS (на базе форка `Learn-Munhwao`).

**Лайфхаки по оптимизации для CPU:**
1. **Использовать формат ONNX:** Библиотека `optimum` позволяет конвертировать модели PyTorch в формат ONNX. На CPU модели в формате ONNX работают в 2-4 раза быстрее и потребляют меньше памяти.
2. **Квантование (INT8):** Загружайте модель Facebook NLLB в сжатом 8-битном формате (`torch.int8`). Модель станет в 4 раза легче и будет быстрее работать на процессоре, потеряв лишь незначительную часть качества.
3. **Пакетная обработка (Batching):** Если нужно перевести большой документ, отправляйте предложения в модель пачками (например, по 8-16 штук), а не по одному.

## 7. Что ИГНОРИРОВАТЬ (Мусор и тупиковые ветви)

При сборке проекта **не тратьте время** на следующие репозитории и подходы:

1.  ❌ **Дообучение (Fine-Tuning) и Back-Translation**
    *   *Причина:* Мы фокусируемся на использовании готовых моделей для быстрого запуска. Репозиторий `hannahchun/nk-sk-nmt-backtranslation` и любые процессы тренировки нейросетей исключаются из текущего плана.
2.  ❌ **`benber86/nkbert`**
    *   *Причина:* В репозитории есть только код обучения BERT, но **НЕТ самих весов модели**. Проект заброшен, модель не загружена. Бесполезен для продакшена.
3.  ❌ **`parksydev/amynai`**
    *   *Причина:* Это просто красивая заглушка (UI) с захардкоженными ответами. `XPDevs/Learn-Munhwao` предоставляет гораздо более глубокий, функциональный и лицензионно чистый (MIT) интерфейс.
4.  ❌ **Попытки обучить модель RU↔NK с нуля (Train from scratch)**
    *   *Причина:* У вас нет миллионов параллельных предложений. Модель будет галлюцинировать. Используйте только подход "Моста" (RU→SK→NK).
